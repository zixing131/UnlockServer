## 方案说明（省电 + 识别率）

旧实现的主要问题：

1. **经典蓝牙每 3 秒做一次 RFCOMM 连接测试**。多数手机/手表没有串口配置文件，探测会失败，于是人在旁边也被判「离开」（#2、#5）。
2. **BLE 也走同一套 `IsInRange`（连接测试）**。设备列表里能看到 RSSI，监控逻辑却当成「连接失败」直接锁屏（#5）。
3. **DeviceWatcher 会回放缓存 RSSI**，设备关机后数值仍不变（#10）。每 15 秒重启 Watcher 会再次写入缓存。
4. **持续主动连接会唤醒对端设备**，更耗电、也更容易被系统限流。

新方案（更接近 Windows 动态锁 / 常见 BLE 近场检测）：

| 能力 | 做法 | 效果 |
|------|------|------|
| BLE 存在检测 | `BluetoothLEAdvertisementWatcher` 被动听广播 | 不连接、省电、RSSI 是当次广播的真实值 |
| 自适应扫描 | 目标稳定在附近时用 Passive；丢失后短暂切 Active | 省电与识别率折中 |
| 经典蓝牙 | DeviceWatcher 的**新** RSSI + 低频 Inquiry，不再用 RFCOMM 当主依据 | 减少误判和耗电 |
| 信号平滑 | 指数滑动平均（EMA） | 压掉 RSSI 抖动（#2） |
| 滞后区间 | 进入阈值比离开阈值更高（更近） | 避免阈值附近反复锁/解锁（#2） |
| 新鲜度超时 | 超过「信号丢失超时」未见新广播则视为离开 | 设备关机可锁屏（#10） |
| 设备发现 | 广播扫描 + 已配对枚举 + 可手动输入 MAC | 提高手表/手环搜到率（#12） |

自动解锁优先走本机凭据提供程序（`UnlockServer.Provider`）；未安装时再回退到 `FileManagerService` / `remoteUnlock`。锁屏使用 `LockWorkStation`，不依赖服务端。

## 逐条

### #1 必须配合远程才能实现解锁吗?

- **现象**：只开解锁工具、未配服务端；离开不锁屏、靠近不解锁。Win10 自带蓝牙锁屏可用。设备：iPhone、华为 GT4。
- **说明**：锁屏可以只靠本程序。Windows 不允许普通程序直接解开登录界面，所以自动解锁需要本机凭据提供程序，或备用的 `FileManagerService` / `remoteUnlock`。
- **处理**：
  - v2.2 增加本机解锁：安装 `UnlockServer.Provider` 后，锁屏界面由系统凭据提供程序提交已保存的 Windows 账号，不再依赖远程服务。
  - 仅开启自动锁定、关闭自动解锁时，保存设置不再强制要求服务器账号密码。
  - 「解锁」页可启用本机解锁，并保留远程服务作为备用；未配置时日志会明确提示。

### #2 有时候在电脑旁边也会有锁定解锁动作

- **现象**：人没离开也会锁，锁完又立刻开，体验差。评论建议加锁定延时。
- **根因**：RSSI 抖动 + RFCOMM 误判 + 无滞后。
- **处理**：EMA、滞后区间、离开/进入持续一段时间才动作（锁定/解锁延迟可配）。

### #3 保存成功后突然丢失蓝牙设备

- **现象**：选中并保存后，界面上的设备马上没了。
- **根因**：`Removed` 被当成真消失；扫描清空列表；未把绑定设备常驻。
- **处理**：绑定设备始终保留；`Removed` 不删设备；只靠新鲜度判断是否在附近。

### #4 怎么调解锁超时

- **现象**：每次解锁要等约 60 秒（旧版写死）。
- **处理**：主界面「解锁延迟」可改，默认 **3 秒**；「锁定延迟」默认 **15 秒**。保存后立即生效。

### #5 BLE 能读到信号，阈值却失效

- **现象**：经典模式读不到 RSSI；BLE 能读到，但阈值远低于当前强度仍锁屏。
- **根因**：监控把 `device.IsInRange`（经典连接测试）当作唯一依据，BLE 从未做该测试，一直是 false。
- **处理**：用新鲜 RSSI + 阈值 + 滞后判断；BLE 以广播为准。

### #6 FileManagerService.exe 和 UnlockServer.exe 怎么配合？

角色分工：

| 程序 | 角色 | 做什么 |
|------|------|--------|
| **UnlockServer.exe**（本工具） | 客户端 / 决策 | 扫蓝牙、判断远近、调用 `LockWorkStation` 锁屏、在需要解锁时连本机解锁服务 |
| **FileManagerService.exe** / **remoteUnlock** | 解锁服务 | 跑在本机（默认 `127.0.0.1:2084`），在锁屏界面用 Windows 用户名密码解锁 |

配合步骤：

1. 安装并启动远程解锁服务（发布包里的 `remoteUnlock` / `FileManagerService`）。
2. 在 UnlockServer 填写本机 IP（一般 `127.0.0.1`）、端口（默认 `2084`）、**Windows 登录用户名和密码**。
3. 点「测试连接」，确认服务在听端口。
4. 搜索并绑定蓝牙设备，设好阈值，打开「自动锁定 / 自动解锁」，保存。

只锁屏、不自动解锁：可以不装服务端，关掉「自动解锁」即可。

v2.2 起优先使用本机凭据提供程序解锁；远程服务仅作备用。

### #8 开启「不干预人工锁定」后开机无法自动解锁

- **现象**：勾选后，开机停在锁屏，人已经在旁边也不解锁。计划任务似乎要最高权限，触发器希望改成「启动时」。
- **根因**：开机锁屏被当成「人工锁定」；`isLockBySoft` 被改成 false。计划任务用 `TASK_CREATE`，已存在则不会更新，且未开最高权限。
- **处理**：
  - 进程启动后一段宽限期内的锁定视为系统锁定，允许自动解锁。
  - 之后真正的 Win+L / 开始菜单锁定仍不干预。
  - 自启：登录后延迟约 15 秒启动（等蓝牙栈），最高权限，`CREATE_OR_UPDATE`。
  - 说明：纯「系统启动」触发时桌面会话往往还没有，不适合带界面的解锁工具，因此用「登录后延迟」而不是 Session 0 的开机触发器。

### #10 设备直接关机，RSSI 长时间不变

- **现象**：BLE 设备关机后 RSSI 像被缓存，不锁屏。UnlockServer v2.0 / Win10。
- **根因**：DeviceWatcher 回放旧 `SignalStrength`；重启 Watcher 会再次写入。
- **处理**：只有新广播或带新 RSSI 的 Updated 才刷新 LastSeen；超过「信号丢失超时」（默认 8 秒）视为离开并锁屏。

### #11 v2.0 怎么下载呢

- WPF 重构版在仓库 `UnlockServer.Wpf`，发布页：[Releases](https://github.com/zixing131/UnlockServer/releases)。
- 历史蓝奏云链接见仓库 README。
- 评论中「能锁不能解、SSL 连接 127.0.0.1:2084 被拒绝」= 本机解锁服务没装或没开。先装 `remoteUnlock_and_UnlockServer` 包里的 remoteUnlock，再测连接。

### #12 红米 Watch 6 扫描不到

- **现象**：关掉手机蓝牙仍搜不到手表。
- **原因**：很多手环/手表连着手机时不再广播；小米/红米常用随机地址；未开心率/发现广播时电脑看不到。
- **处理**：
  - 设备列表用 **Active BLE 广播扫描** + 已配对设备。
  - 支持「全部」同时扫经典蓝牙和 BLE。
  - 支持手动输入 MAC。
  - 界面提示：断开与手机的连接、打开可被发现/心率广播后再扫。
- **仍搜不到时**：在手表上打开广播或发现模式，或先与 Windows 配对再刷新；也可在手表/手机蓝牙详情里抄 MAC 手动绑定。

### #14 锁屏界面倒计时、测试状态，以及远程/手动切换

- **v2.3.1 后续修复**：暂停锁屏后的线程死锁、搜索窗口重复释放扫描、类型过滤与 UI 更新积压、静默扫描恢复。构建结果和仍需实机确认的项目见 [蓝牙稳定性回归说明](bluetooth-stability-testing.md)。

- **倒计时和靠近的关系**：先持续靠近满「靠近后解锁」，再开始「操作前提示」倒计时，倒计时结束才解锁。
- **倒计时上滑**：提示一开始要上滑一次，把锁屏壁纸划开，倒计时才能显示。原先连滑 5 次，多出来的 4 次没有作用，已去掉。倒计时结束后提交解锁时，仍会再上滑。
- **测试状态**：测试结束后没有把标题改回去，所以一直停在「解锁测试中」。现已在测试结束时恢复为「监控中」。
- **远程循环**：断开远程桌面会记成手动锁定；输入密码解开会记成手动解锁。两个「不干预」都打开时，就会出现离开不锁屏、回来不能自动解开的循环。
- **处理**：
  - 规则页增加「有信号时仍锁屏」。打开后，即使开了「不干预手动解锁」，只要这次使用中看到过蓝牙，信号断开仍会自动锁屏。远程时一直没有蓝牙，则不会锁屏。
  - 锁屏磁贴增加「点击解锁」，排在「取消本次解锁」上面。设备在旁边时由软件解开，并记成自动解锁，之后信号断开仍会锁屏。设备不在旁边时只提示，不提交密码。
  - 锁屏按钮要重新编译并安装凭据提供程序后，下次锁屏才看得到。

## 建议设置（起步）

| 项 | 建议 | 说明 |
|----|------|------|
| 蓝牙类型 | 手表/手环选 BLE；老耳机等选经典 | 红米/小米手表走 BLE |
| 信号阈值 | 先 `-70`，再按实际微调 | 越接近 0 越强；想「更近才解锁」把阈值改大（如 `-55`） |
| 滞后 (dB) | `8` | 防止在阈值附近抖 |
| 信号丢失超时 | `8` 秒 | 关机/走远后多久开始算离开 |
| 锁定延迟 | `15` 秒 | 离开持续这么久才锁屏 |
| 解锁延迟 | `3` 秒 | 靠近持续这么久才解锁 |
| 不干预人工锁定 | 按需 | 开机第一次仍可自动解锁；之后手动锁不会自动开 |
| 有信号时仍锁屏 | 常切换远程时打开 | 手动解锁后，蓝牙曾经在旁边，离开仍会锁屏 |
